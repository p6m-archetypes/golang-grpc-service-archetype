# {{ project_title }}

Go gRPC service generated by `golang-grpc-service-archetype`.

## API

The p6m standard gRPC surface — service `{{ project_name }}.{{ ProjectName }}`
with full CRUD over the `{{ EntityName }}` entity (`{ id, display_name }`):
`Create{{ EntityName }}`, `Get{{ EntityName }}`, `List{{ EntityName }}s`, `Update{{ EntityName }}`,
`Delete{{ EntityName }}` — plus server reflection and `grpc.health.v1.Health`.

Health (`/health/readiness`, `/health/liveness`) and Prometheus `/metrics` answer over HTTP on the
management port.

The proto contract lives at `proto/{{ project_name }}/{{ project_name }}.proto`;
the service implementation is `internal/service/service.go`.

## Environment

The platform injects: `GRPC_PORT`, `MANAGEMENT_PORT`, `LOGGING_STRUCTURED`,
`DB_HOST`/`DB_PORT`/`DB_USERNAME`/`DB_PASSWORD`/`DB_DBNAME` (when persistence is selected),
`OTEL_SERVICE_NAME`, and `OTEL_EXPORTER_OTLP_ENDPOINT` (traces export iff set).

## Getting started

### Generate protobuf code

```bash
make proto
```

This runs `buf generate` and produces Go code under `gen/`. The Docker builds run the same
codegen themselves (via `protoc`), so a clean render builds and serves its API out of the box —
`make proto` is only needed for local, on-host builds.

### Build

```bash
make build
```

### Test

```bash
make test
```

### Run

```bash
make run
```

gRPC on port `{{ service_port }}`, HTTP management on `{{ management_port }}`.
